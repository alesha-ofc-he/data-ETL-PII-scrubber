# Решения на этапе данных

1. **Исследование через notebook + воспроизводимый CLI.** Ноутбук показывает EDA и гипотезы, а загрузка, валидация и split живут в Python-модулях. Все важные шаги можно повторить без интерактивного исполнения ячеек.
2. **Группы одинаковых признаков.** Одинаковые строки иначе могут оказаться и в train, и в test. Стабильный идентификатор группы не подаётся в модель.
3. **Без выдуманной временной проверки.** Публикация UCI объясняет горизонт метки, но не содержит отдельной даты среза для каждой строки. Временной holdout из этого файла честно не построить.
4. **Осторожность со спорными колонками.** `Status` и `Customer Value` исключены до абляции; если выяснится, что они доступны в момент решения, это будет отдельный эксперимент только на development-частях.
